# Cấu Trúc Và Phân Loại Các Tập Dữ Liệu Trong Thư Mục /Data

Phần kiến trúc này giải thích sự khác nhau về bản chất dữ liệu giữa các thư mục con phân vùng tại `/Data/`. Toàn bộ dữ liệu dù ở thư mục nào cũng phải trải qua tiến trình chuyển hóa các đối tượng thành mảng giá trị Embedding trong tập cấu hình `items_features.csv`.

**Lưu ý quan trọng:** Dữ liệu ở các thư mục là **không hoàn toàn giống hệt nhau**. Chúng đại diện cho các `kịch bản thử nghiệm (Test cases)` độc lập với môi trường thiết lập chênh lệch theo chiều sâu. Sự khác biến này diễn ra tại đặc tả file `items_features.csv` và dữ liệu tương tác người dùng:

## 1. Sự Khác Biệt Về Quy Mô Tương Tác Của Người Dùng (1p, 3p, 5p)
*   **Đối tượng chứa cấu trúc khác biệt:** Các file `train.txt`, `test.txt`.
*   **Phân tích kỹ thuật:** Thể hiện tỷ lệ lấy mẫu từ quần thể Interaction thực tế. Tập `1p` trích xuất `1%` tương tác ngẫu nhiên để cung cấp tính năng Debug nhanh và theo dõi đường cong Loss. Tập `5p` mở rộng dung lượng cung cấp mô phỏng khối lượng đào tạo tiệm cận ứng dụng, với tỷ lệ chi phí đồ hoạ văng cao hơn. 

## 2. Sự Khác Biệt Trong Cách Gộp Embedding Ảnh (m1, m2, m3)
*   **Đối tượng chứa cấu trúc khác biệt:** Cột giá trị `feature3` trong `items_features.csv` và các biến thể dataset được notebook `Eval_All.ipynb` gọi ra.
*   **Phân tích kỹ thuật:** `m1`, `m2`, `m3` không phải là 3 backbone CNN khác nhau. Chúng là 3 chiến lược gộp embedding ảnh:
    *   `m1`: mean fusion - lấy trung bình các vector ảnh.
    *   `m2`: weighted fusion - gộp theo trọng số.
    *   `m3`: max fusion - lấy phần tử lớn nhất theo từng chiều.
*   **Mục tiêu:** So sánh cách gộp nào tạo similarity matrix tốt hơn cho graph recommender.

## 3. Sự Khác Biệt Tại Khâu Tiền Xử Lý Chủ Thể Quần Áo (vcr vs vcr_detect)
*   **Đối tượng chứa cấu trúc khác biệt:** Bản chất chất lượng Vector lưu ở cột `feature3`.
*   **Phân tích kỹ thuật:** 
    *   `vcr`: Trích xuất vector từ nguyên gốc ảnh. Vector mang thêm nhiễu đặc trưng tạp từ Cảnh Nền, Đầu người, Phụ kiện, v.v.
    *   `vcr_detect`: Trích xuất vector thông qua cổng Crop giới hạn Bounding Box bằng bộ nhận dạng YOLOv5s. Kỹ thuật này làm sạch tín hiệu hệ thống, chỉ cấu trúc Vector thể chất loại bỏ 100% Background (phông nền dư), hỗ trợ nhúng thông tin lên chuẩn xác hơn vào mạng đồ thị GCN.

## 4. Sự Khác Biệt Ở Module Kết Hợp Đa Thể Thức (Late Fusion, Attention)
*   **Đối tượng chứa cấu trúc khác biệt:** Cách tính similarity matrix và cách lưu cache `.npz`.
*   **Phân tích kỹ thuật:** Các biến thể như `_late_fusion`, `_aggregation`, `_weightattention`, `_multiheadattention`, `_pca` là các chiến lược kết hợp text + image khác nhau trước khi sinh ma trận kề.
    *   Một số biến thể gộp trực tiếp embedding, một số gộp sau khi tính similarity, một số dùng attention để học trọng số.
    *   Mỗi biến thể có thể tạo folder dataset riêng để tách cache và checkpoint khi benchmark.

## Kết luận triển khai:
Trường hợp tái sử dụng Source Code cho môi trường thực tế doanh nghiệp, tiến trình không yêu cầu bảo lưu tất cả cấu trúc phiên bản giả lập này. Triển khai chỉ cần xác định ra **phương pháp mang lại hiệu năng/chi phí tài nguyên lý tưởng nhất** (Ví dụ kết hợp `vcr_detect` + `vcr1p_img_m1_weightattention`) và nạp file đặc tả `.csv` Production thay thế, quy trình huấn luyện đồ thị sẽ lập tức khởi chạy tự động.
