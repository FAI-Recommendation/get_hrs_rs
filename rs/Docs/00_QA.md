## Workflow đầy đủ

```
┌─────────────────────────────────────────────────────────────┐
│                    PHASE 1: Tiền xử lý                      │
│                   (chỉ chạy 1 lần, cache npz)               │
└─────────────────────────────────────────────────────────────┘

items_features.csv
  └── feature3 (cột ảnh)
        │
        │  CLIP          → mỗi ảnh = vector [0.12, 0.34, ..., ] 512 số
        │  MobileNetV2   → mỗi ảnh = vector [0.12, 0.34, ..., ] 768 số
        │
        ↓
  Tính cosine_similarity(ảnh_i, ảnh_j) cho mọi cặp sản phẩm
        │
        │   Kết quả chỉ là 1 số (0.0 → 1.0) per cặp
        │   512 hay 768 chiều → đều ra scalar giống nhau
        │
        ↓
  s_img_similarity_adj_mat.npz
  Matrix N×N (N = số sản phẩm)
  ← CLIP và MobileNetV2 đều ra cùng shape, khác giá trị


┌─────────────────────────────────────────────────────────────┐
│                    PHASE 2: Training GCN                     │
│              (embed_size=512 hoạt động ở đây)                │
└─────────────────────────────────────────────────────────────┘

User/Item IDs
      │
      ↓
nn.Embedding(n_users, embed_size=512)   ← GCN tự học
nn.Embedding(n_items, embed_size=512)   ← GCN tự học
      │
      │   Input: ma trận adj (interaction + similarity)
      │   Đây là nơi dùng file npz từ Phase 1
      │
      ↓
  LightGCN Layer 1  (512 → 512)
      ↓
  LightGCN Layer 2  (512 → 512)
      ↓
  LightGCN Layer 3  (512 → 512)
      ↓
  LightGCN Layer 4  (512 → 512)
      ↓
  User vector (512)  ·  Item vector (512)  →  score
      ↓
  BPR Loss → backprop → cập nhật embedding
```

## Kết luận

```
CLIP (512)  ─────────┐
                      ├── Tính similarity → npz → làm đầu vào adj matrix
MobileNetV2 (768) ───┘

                      embed_size=512 ← GCN tự học, không liên quan đến ảnh
```

**512 của CLIP** = số chiều của vector ảnh thô từ model CLIP

**768 của MobileNetV2** = số chiều của vector ảnh thô từ MobileNetV2

**512 của embed_size** = số chiều GCN **tự học** để biểu diễn user/item

→ Chúng ở 2 phase khác nhau hoàn toàn, không ảnh hưởng lẫn nhau.

## Phân loại từng variant

| sim_type | Loại | Nguồn signal |
|----------|------|-------------|
| `none` | **CF thuần** | Chỉ dùng lịch sử mua hàng (user↔item) |
| `tfidf` | **Hybrid** | CF + CB (text similarity) |
| `img_only` | **Hybrid** | CF + CB (image similarity) |
| `multimodal` | **Hybrid** | CF + CB (text + image similarity) |

---

## Chi tiết từng thành phần

**CF — Collaborative Filtering** (`interaction_adj`):
```
"User A và B cùng mua sản phẩm giống nhau
 → A và B có taste giống nhau
 → recommend cho A những gì B thích"
```
Học từ `train.txt` — không cần biết sản phẩm là gì.

**CB — Content-Based** (`similarity_adj`):
```
"Sản phẩm X và Y có mô tả/hình ảnh giống nhau
 → X và Y similar
 → ai thích X thì cũng nên thích Y"
```
Học từ `items_features.csv` — không cần biết ai mua gì.

**Hybrid** = cộng cả 2 trong mỗi GCN layer:
```python
item_next = item_interaction   # ← từ CF
          + item_similar       # ← từ CB
```

---

## Tại sao thiết kế này hay

Giải quyết **cold-start problem**:
- Item mới chưa có ai mua → CF không có signal → nhưng CB vẫn hoạt động được dựa trên content
- User mới chưa mua gì → CB không giúp được → nhưng CF vẫn dùng được nếu có vài interaction

**Đây chính là lý do tồn tại của CombiGCN** — kết hợp CF và CB trong cùng một graph propagation thay vì train riêng rồi ensemble.
